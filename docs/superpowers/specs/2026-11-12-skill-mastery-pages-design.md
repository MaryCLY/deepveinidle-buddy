# 按技能绑定的精通页估算

状态：本地内测 0.5.8-beta.1。开发基线为助手 0.5.7、游戏资源 1.0.1214。

## 目标与依据

玩家采矿时也会查看锻造配方。估算应回答“以当前角色执行这项工作，按该技能绑定的精通配置，需要多久、能得到多少产物”。每个动作使用自身技能对应的一整页精通，缺少绑定或对应页时使用当前生效页。切页等待按零处理，忽略冷却、待切换页及动作先后顺序。

2026-11-12 在 Chrome 已登录的游戏会话中，只读确认了以下示例。第 1 页生效，含采集精通 104、稀有精通 105，采矿等采集技能绑定第 1 页。锻造、烹饪等制造技能绑定第 2 页，含制造精通 106。0.5.7 只投影当前页的等级。此样本确认多页数据可读；无绑定、空页及异常输入另用夹具验证。

## 输入与选页

从同一角色、同一份快照读取以下字段。实时客户端与已有连接收到的角色快照共用投影规则。

| 字段 | 含义与采集范围 |
| --- | --- |
| `masteryPage` | 当前生效页号。基线支持整数 1、2、3。 |
| `masteries` | 当前生效页的已分配等级。 |
| `masterySkills` | 技能 ID 到页号的映射，仅提取助手支持的工作技能。 |
| `masteryAway` | 以页号为键的其他已拥有页。保留页是否存在，即使投影后为空对象。 |

对每个实际工作动作，先取游戏配方或采集来源的技能 ID，再按下表选择等级。一次估算内共享同一份快照。

| 条件 | 本动作使用的等级 |
| --- | --- |
| 技能没有绑定，或绑定到当前页 | `masteries` |
| 绑定到另一页，且该页存在 | `masteryAway[绑定页号]` |
| 绑定到合法页号，但页表中没有该页 | `masteries` |
| 绑定页存在且为空，或只有与本动作无关的精通 | 使用该页。游戏采用稀疏等级表，合法页内缺少的精通项按 0 级解释。 |

每页只投影现有公式使用的 `craft`、`gather`、`rare`，已提供的等级须为 0 至游戏上限（基线为 200）的整数。各页独立解释，推导出的模拟角色只替换精通等级，其他角色修正继续来自同一次角色采样。

**兼容与异常。** 旧快照完全缺少三个分页字段时，沿用当前 `masteries`。单页角色可显式提供当前页号和两个空映射。部分分页字段缺失、映射结构损坏、受支持技能绑定非法页号、已提供的相关等级非法，均视作无效分页输入。空页必须是合法对象，`null` 属于损坏。走既有同步错误与有效数据保留流程，恢复后重新估算。当前等级表缺失或结构非法时沿用角色导入失败流程（`incompleteSnapshot`），保留同角色最近一次有效结果；尚无有效快照时显示不可计算。只使用一个来源的数据，禁止从前一角色或另一来源补齐页表。

## 计算与界面

- 制造候选、订单行与收藏（制造）按各自来源技能估算。收藏（采集）的品质分布、预计产量、达到目标的期望次数与每百点耗时使用采集来源的有效页。沿用上游公式决定哪些结果受精通影响；固定耗时升级和只产普通品质的采集仍遵循各自配方规则。
- 混合技能订单逐动作计算后汇总。收藏计划展开金属锭、切割宝石时，半成品按自身配方技能选页。相同动作在“全部技能”和单技能筛选中得到相同的单次估算。切换筛选或列表排序不会决定模拟角色的精通。
- 候选排序、阈值、完整材料需求、预计产物抵扣、采购金额、工时费及计划合计复用逐项结果。制造指定次数、收藏目标、收藏点数档位和市场价格等输入沿用现有规则。
- 桌面与移动共用计算。无需设置开关或手动选页。执行预填仍填入最新结果对应的游戏草稿；动作高亮继续反映游戏真实任务与队列。

## 接入与更新

建议在现有只读角色采集、角色导入与工作角色构造之间传递页配置，在知道具体动作技能的计算入口解析有效等级。这样候选、订单和半成品可共享一条选页规则。在筛选器或订单级别只选一次页无法表达混合技能，真实切页还会改变游戏状态。

- 页号、绑定、当前页或其他页的相关等级发生变化时，按现有同步节奏刷新。正常前台在 1 秒内更新计算，收藏候选缓存须感知有效输入变化。单纯浏览游戏中的另一页不会改变生效页。
- 执行草稿的完整输入签名按固定技能与精通项顺序纳入各支持技能实际用于公式的等级。等待期间任一技能的有效等级变化，都按现有完整输入守卫中止并提示；单换页号而有效等级相同、对象键顺序改变，均允许继续。购买草稿继续比较最新目标商品的请求。普通 tick 和采样时间继续按既有签名规则处理。
- 精通配置只存角色会话内存。切换角色时重新取样。已有 version=2 订单在载入当前角色后重新估算，订单条目不保存精通页号。助手仅通过既有读取路径获得数据，模拟不调用切页、改绑或开始工作的接口。

## 验收

下表是实施后的验收条件。计算对照使用同一套现有公式：为单项动作单独准备角色，将目标页的完整等级作为当前等级输入，所得单项结果应与自动选页相同。

| 场景 | 预期 |
| --- | --- |
| 当前页只含采集 104、稀有 105，锻造绑另一页且该页只含制造 106 | 锻造与仅使用制造 106 的对照一致；采矿与仅使用当前页的对照一致。交换动作计算顺序仍一致。 |
| 两个同类工作技能分绑不同等级的页 | 同一制造列表中分别命中各自的对照；混合订单的总工时等于各行工时之和。 |
| 无绑定、绑定当前、绑定合法但未拥有页、三个分页字段全部缺失 | 各自与当前页对照一致。 |
| 绑定有效空页或仅含无关精通的页 | 与零相关等级的对照一致，即使当前页有高等级加成。 |
| 切换当前页、解绑、修改非当前绑定页等级 | 下一份有效快照到达后候选、既有订单与计划使用新配置。已绑定且有效等级相同的动作数值稳定，无绑定动作跟随当前页。 |
| 收藏采集与半成品展开 | 品质明细、次数和时间分别匹配对应动作的对照；半成品工时、采购和工时费与逐项汇总相符。纯煤品质与升级固定耗时符合配方规则。 |
| 数据无效、随后恢复，或切换来源／角色 | 异常可见，恢复后错误清除；各角色、各来源独立。采样与恢复均不把页配置写入用户存档。 |
| 桌面和移动预填期间改绑 | 执行按完整输入守卫处理，购买按目标请求守卫处理。全程没有切页、改绑或提交动作。 |

验证分两层：单元测试覆盖采集投影、兼容与非法输入、逐技能角色构造及数值对照；隔离浏览器覆盖同步刷新、缓存、混合计划、预填守卫和存档回读。真实账号观察只证明当时可读的字段和样本值。发布验证按[发布流程](../../releasing.md)执行。
